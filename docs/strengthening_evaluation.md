## 二、審稿人或老師最可能問的問題

| 問題 | 目前怎麼回答 | 夠不夠 |
|---|---|---|
| 能耗沒有量測，怎麼信？ | 參數取自已發表的整板量測（z2_anchor 用同一塊 PYNQ-Z2 校準：1.67 W 對模型 1.70 W）；四組參數都報；改用 Vivado 功耗時，B1 在 margin 1–5 仍多耗 26–108%、B2 多耗 10–40%（m8 的 B1 幾乎一樣） | 期中夠，論文要寫成範圍並標「估計」 |
| 只合成單一節點，整個設計真的放得下、跑得到時脈嗎？ | 節點加總 LUT 24k、DWC 2.4k、預估 FIFO 很少，約晶片的 53%；關鍵節點繞線，最慢的一層改窄後到 125 MHz；+10% 那欄就是時序打折的情況 | 部分。**這是最大的技術缺口** |
| 只有一個網路？ | 承認是限制。C1 的 DSP 缺口不限於 ResNet-8，兩條路都會碰到：
  - 預設設定（`standalone_thresholds = False`）：乘法模組吸收門檻，走 HLS 版，碰到的是「resType auto 用 DSP、FINN 估 0」。
  - 打開獨立門檻後：走 RTL 版，只要「兩個運算元都 ≥ 4 bit、有一個 > 4 bit、PE ≥ 3」就少算一半；例如吃 8-bit 像素、權重 ≥ 4 bit 的第一層。 | 期中可以接受，寫成限制和推廣的論述 |
| 準確率用測試集選？ | A′ 和所有基準用同一標準，已列為限制 | 可以接受 |
| 「LUT 估計不準早就知道了」 | 引用 Jentzsch、Diaconu、FINNAS；我們的新意是具體缺陷、規則和 DSE 傷害 | 夠（`related_work.md`） |
| 「越寬越慢早就知道了」 | 引用 Alam 2022；新意是同 lane 數下的 SIMD/PE 分配，以及 FINN 文件建議先展開 SIMD | 夠 |
| C4 沒有實驗？ | 標成模型推導，附事先寫下的預測 | 弱；有朋友的計時數據會好很多 |

## 四、建議

**結論：不需要再做大型補強，現在最重要的是開始寫論文和簡報。**

- **理由：**
  - C1、C2 的證據已經很強。
  - C3 的主要缺口是功率實測和完整實作。功率沒有功率計做不了；完整實作在 Windows 上風險高、要 3–6 小時。這兩點用「Vivado 功耗交叉檢查」「+10% 時序」「DWC 全合成」已經各自框出範圍。
  - 剩下的時間投入寫作，報酬遠高於再補一個實驗。
- **建議的安排：**
  1. 現在開始寫論文（我起草，你審）。數值一致性跑完自動補上（A）。
  2. 問朋友的上板計時（B）。數據到了，我 30–60 分鐘內整合進 C4。
  3. 可選：背景重訓驗證集（D），不佔寫作時間。
  4. 論文初稿完成後，如果 11/1 晚上前還有餘裕，再考慮 C（最多 3 小時，做不出來就列為未來工作）。
  5. FINN issue（E）由你決定要不要發。
- **時間表（建議）：**
  - 10/31 下午到晚上：論文第 1–4 節初稿。
