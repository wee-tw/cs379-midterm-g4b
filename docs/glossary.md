# 名詞白話解釋

給沒有 FPGA 或機器學習背景的人。大致照「先懂這個，才懂下一個」的順序排。

## 神經網路

| 名詞 | 白話 |
|---|---|
| ResNet-8 | 很小的影像分類神經網路，約 7.7 萬個權重。MLPerf Tiny 拿它當標準考題。「Res」指殘差：資料除了走主路，還有一條捷徑直接加回來。 |
| CIFAR-10 | 10 類的小圖片資料集（飛機、汽車、鳥…），每張 32×32 像素。訓練用 5 萬張，測試用 1 萬張。 |
| MLPerf Tiny | 業界公認的小型 AI 硬體評比，規定了模型和量測方法。 |
| 準確率 | 1 萬張測試圖裡猜對幾 %。浮點版 ResNet-8 是 86.25%。 |
| 量化、W/A 位元 | 把權重（W）和中間結果（A，activation）從 32 位元浮點數改成用少數位元存。例如 W4A4 = 權重 4 位元、中間結果 4 位元。位元越少，硬體越小越省電，但準確率會掉。 |
| QAT | 量化感知訓練：訓練時就模擬低位元，讓模型適應，準確率掉得比較少。 |
| Brevitas | 做 QAT 的 PyTorch 套件，FINN 指定用它。 |
| 知識蒸餾（KD） | 訓練時讓量化模型模仿一個準確率較高的浮點模型（老師），通常能多一點準確率。 |
| 混合精度 | 網路不同段用不同位元數，而不是全部一樣。 |
| G1–G4、`44444448` | 我們把網路分 4 組：G1 = 開頭的卷積加第 1 段，G2 = 第 2 段，G3 = 第 3 段，G4 = 最後的分類層（FC）。8 個數字依序是 G1 的 W、A，G2 的 W、A，G3 的 W、A，G4 的 W、A。`44444448` = 前三組都是 W4A4，FC 的權重 4 位元、輸入 8 位元。 |
| 統一精度 | 全網路同一種位元數，例如全部 W4A4。 |
| margin（門檻） | 準確率最低要多少。margin 1 = 84.37%，每加 1 就放寬 1 個百分點，margin 8 = 77.37%。 |
| seed | 訓練的隨機種子。同一個設定換 seed 重訓，可以看準確率的起伏。margin 1–5 選定的配置我們都跑了 3 個 seed。 |

## FPGA

| 名詞 | 白話 |
|---|---|
| FPGA | 可以重新「接線」的晶片。它不像 CPU 那樣跑程式，而是直接把電路排出來，所以能做專用的加速器。 |
| PYNQ-Z2 | 我們用的 FPGA 開發板，晶片是 Zynq-7020：一半是 ARM 處理器，一半是 FPGA。 |
| LUT | FPGA 最基本的邏輯積木。Zynq-7020 有 53,200 個。 |
| DSP（DSP48） | 專門做乘法的硬體單元。只有 220 個，很容易不夠用。 |
| BRAM（BRAM18） | 晶片上的小塊記憶體，一塊 18 Kbit，共 280 塊，只能整塊使用。 |
| LUTRAM | 拿 LUT 當小記憶體用。小的權重表放這裡，常常比放 BRAM 划算。 |
| 資源預算 | 我們規定設計最多用晶片 80% 的 LUT（42,560 個），留空間給繞線和周邊電路。 |
| 合成（synthesis） | 把硬體描述轉成真正電路的步驟，做完才知道實際用了多少 LUT、DSP、BRAM。一次可能要幾十分鐘到幾小時。 |
| Vivado、Vitis HLS | AMD（Xilinx）的官方合成工具。我們把它們的結果當成「真正的硬體用量」。 |
| RTL、HLS | 兩種寫硬體的方式。RTL 直接描述電路；HLS 從 C++ 自動產生電路。FINN 兩種模組都有。 |
| 寬度轉換器（DWC） | 前後兩個模組一次傳的位元數不同時，FINN 插在中間的小模組，把資料「拆開」或「併起來」。寬轉窄（例如一次 960 位元拆成每次 15 位元）每個輸入位元約要 1 個 LUT；窄轉寬幾乎不用 LUT。FINN 的估計不分方向：窄轉寬估太多、寬轉窄估太少。 |
| 時脈、FPS | 時脈是電路的節拍，例如 125 MHz；FPS 是每秒處理幾張圖。 |
| 每張能耗（mJ） | 處理一張圖花多少電。1 mJ = 千分之一焦耳。 |

## FINN 和設計搜尋

| 名詞 | 白話 |
|---|---|
| FINN | AMD（Xilinx）的開源工具，把量化後的神經網路自動變成 FPGA 加速器。每一層都有自己的專用硬體，像生產線一樣串起來（dataflow）。我們用 v0.10.1，這是最後一個支援 PYNQ-Z2 的版本。 |
| 估計器 | FINN 內建的公式，不用合成就先估每層要多少 LUT、DSP、BRAM。很快，但不一定準：這就是 C1、C2 的主題。 |
| MVU／MVAU | FINN 裡做矩陣乘法的模組，是最大的一塊硬體。 |
| 門檻（threshold） | FINN 用「和一串門檻比大小」來把中間結果量化。A 位元要 2^A − 1 條門檻，8 位元就要 255 條，很佔記憶體。 |
| folding、PE、SIMD | 平行度。PE × SIMD = 每個時脈同時做幾個乘法。越大越快，但用越多資源。 |
| 輸入摺疊（SF） | SF = MW / SIMD：一個輸出要分幾個時脈才把輸入讀完。SF = 1 代表一次讀完。SF > 1 時，SIMD 個乘積的加總要和累加在同一個時脈完成，SIMD 越寬越慢。 |
| 時序、關鍵路徑、WNS | 電路最慢那條路徑要多少 ns，決定時脈最高能開多少（例如 8 ns 對應 125 MHz）。WNS 是離目標還差多少，負的代表做不到。 |
| 合成後 vs 繞線後 | 合成只決定用哪些邏輯；佈局繞線（place & route）再把它們擺到晶片上並接線，接線也有延遲。我們的時脈等級用合成後的數字，再挑 28 個關鍵節點做繞線檢查：25 個繞線後能跑的時脈等級和合成後判斷的一樣，3 個寬節點慢一級。 |
| 繞線餘裕 | 把合成後的週期乘上 1 + 餘裕（例如 +10%、+20%）再分時脈等級，用來看繞線變慢時結論會不會變。 |
| 時脈等級 | 我們依每個節點實測的時序，替每個設計找出它能用的最高 PYNQ 時脈（125、111、100…MHz），能耗就用這個時脈算。 |
| 時序安全的重新摺疊 | 把 SIMD 太寬的乘法模組改窄（RTL SIMD ≤ 12、HLS SIMD ≤ 18）、PE 加大，乘法數大致不變（所以速度和 DSP 數不變），讓它在繞線後也能跑 125 MHz（RTL）或 111 MHz（有摺疊的 HLS）。 |
| 實作模式 | 乘法放在哪種資源上：`lut` 用 LUT；`dspc`、`dsp4c` 用 DSP，DSP 數照實際產生的電路計算。 |
| T | 每張圖的目標時脈週期數，越小越快。 |
| DSE | 設計空間探索：在所有組合中自動找最好的設計。我們的空間是 6,561 種位元組合 × 3 種實作模式 × 12 種速度，再加上每層的實作選擇和時脈。 |
| 成本模型 v2.1 | 我們用合成結果校正過的硬體用量模型，用來取代 FINN 的估計器。 |
| A′ | 我們的方法：同時挑位元數、平行度、實作方式和時脈，讓每張能耗最低。 |
| B1–B5 | 比較基準。B1：最好的統一精度。B2：用 BOPs 挑位元，配 FINN 預設設定。B3：B2 的位元再做硬體搜尋。B4：同樣的空間，但追求最快。B5：最快的設計，做完一張就停時脈。 |
| BOPs | 位元運算量（乘法次數 × 位元數）。常被拿來代表硬體成本，但反映不出 FPGA 實際用了多少資源。 |

## 評估指標（主要是 C2）

| 名詞 | 白話 |
|---|---|
| Kendall τ | 兩種排名有多像。1 = 完全一樣。 |
| Feasible@K | 估計器排前 K 名的設計中，真的放得進晶片的比例。 |
| 白跑的合成次數 | 照估計器的排名一個一個合成，在遇到第一個放得下的設計之前，失敗了幾次。 |
| regret | 最後選到的設計，比真正最好的設計多耗幾 % 的電。 |
| ADRS | 估計器找到的「最佳取捨曲線」和真正的曲線平均差多少。 |
| 功耗參數 nominal、z2_anchor | 能耗模型的兩組主要參數。nominal 用文獻典型值；z2_anchor 用 MLPerf 在同一款 PYNQ-Z2 上量到的 1.67 W 校準。 |
| 留一設計誤差（LODO） | 校正模型時拿掉一個設計，用其餘設計擬合，再預測被拿掉的那一個，看誤差多少。 |
